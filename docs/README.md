# cd4 문서 안내

2026-10-04(Asia/Seoul)에 기존 프로젝트를 조사한 기록이다. 후속 채팅에서 라이브러리를 업데이트하고 기존 문서를 현행화할 때 이 안내부터 읽는다.

2026-10-05 승인된 계획에 따라 Next.js 16과 관련 라이브러리 업그레이드를 실행했다. 현재 결과는 [업그레이드 변경·검증 기록](next16-upgrade-verification-2026-10-05.md)을 먼저 읽는다. 서버 빌드와 대표 경로의 정적 export를 검증했으며, 전량 정적 빌드는 사용자의 결정에 따라 공간 확보 후 진행한다. [현황과 순차 계획](next16-upgrade-assessment-2026-10-05.md), [의존성 조사](next16-dependency-audit-2026-10-05.json), [검사 기준선](next16-baseline-2026-10-05.json)은 업데이트 전 기록이다.

## 읽는 순서

| 문서 | 역할 |
| --- | --- |

| [DAG 연동 계약](dag-integration.md) | 별도 DAG 저장소의 CD 파이프라인, DB·식별자·기준일·순위·공개 시점 계약 |

위 세 문서는 **업데이트 전 조사 기준점**이다. 라이브러리 최신화나 문제 수정이 완료되었다는 의미가 아니다. 이후 작업에서 해결한 항목은 작업일·변경 코드·검증 결과를 덧붙이고, 과거 조사 결과를 현재 상태인 것처럼 유지하지 않는다.

## 문서와 코드의 기준

- 제품 목적과 범위는 사용자가 밝힌 의도를 기준으로 한다. 후속 제안은 채택된 결정과 구분한다.
- 구현·버전·배포 설정은 실제 소스, `package.json`, lockfile, workflow를 기준으로 재확인한다.
- 운영 DB 대상, Dagster 활성화·성공 실행, 실제 배포 모드와 사이트 데이터 기준일은 운영 확인이 필요하다. 로컬 파일의 존재만으로 운영 상태를 확정하지 않는다.
- 문서의 소스 링크는 파일 상대경로다. 라인 번호는 조사 시점의 위치이며, 후속 변경 뒤에는 함수명·설정 키를 함께 확인한다.
- `../../dag/...` 링크는 `silla/cd4`와 `silla/dag`를 형제 디렉터리로 둔 로컬 작업 환경을 전제로 한다. cd4만 clone한 환경에서는 별도 DAG checkout을 연결한다.

## 별도 채팅의 시작 문맥

> `docs/README.md`부터 조사 문서 세 개를 읽고 현재 코드와 차이를 확인한다. cd4는 한국 주식의 숫자와 순위를 쉽게 확인하는 독립적인 조회 서비스이며, Stock Explain MVP와 제품 통합을 전제하지 않는다. DAG의 주식 담당은 CD이고 IS는 별도 Isshoo 파이프라인이다. 기존 타입 오류와 배포·데이터 갱신 문제를 업그레이드로 새로 생긴 오류와 구분한다. 최신 버전과 호환성은 작업 시점의 공식 문서로 확인한 뒤 라이브러리를 업데이트하고, 검증 결과에 맞춰 기존 문서를 현행화한다.
