# cd4 문서 안내

이 디렉터리는 2026-10-04의 초기 조사와 이후 변경 기록을 함께 보관한다. 현재 CD·tem 업무 데이터 구현은 아래 최신 계약과 검증 기록부터 읽는다.

## 최신 프론트엔드 — 2026-10-09

[기존 화면 복원 및 기능 개선 기록](frontend-restoration-2026-10-09.md)에 28개 페이지의 복원 범위, 정확한 숫자·기간 분석·회사 합산·기존 URL·CSV 개선과 전후 캡처를 정리했다. 현재 DB와 공식 순위를 유지하며 `536bd79` 화면 구조를 회복했다. 170개 테스트·타입 검사·변경 파일 lint·Webpack 빌드·28개 경로 검증을 통과했다. 기존 전체 lint 문제와 Turbopack 빌드 환경 제한, 실제 DB 이력 범위는 해당 문서에서 구분한다. 배포·DB 변경·tem 변경은 수행하지 않았다.

tem은 원천 수집·정정·당시 종목 연결과 공식 최신값·마지막 제공값·회사 합계·순위의 계산/검증/공개를 담당한다. CD는 현재 공개 결과를 조회하고 결측·완전성·기준일을 표시하며 선택 기간의 간단한 분석을 수행한다. 업무일은 한국 자정 timestamptz, bigint/numeric/revision DTO는 정확한 십진 문자열이다.

신규 빈 DCD `192.168.50.27:25433/dcd`에 `silla` 계정으로 0000 → 0001 → 0002 설치를 완료했다(PostgreSQL 18.6). 빈 DB 사전 확인 후 최초 설치와 0002 후속 적용을 수행했고, 0002 적용·재실행 no-op 모두 exit 0이었다. 0002는 컬럼·입력 형식을 유지하면서 사용자 정의 함수 4개·trigger 8개를 제거하고 단순 CHECK 3개를 추가했다. 2026-10-07 05:16:56 KST에 최종 catalog·세 migration hash를 확인했으며 14개 업무 테이블은 모두 0건이다. 기존 데이터 이전·baseline은 수행하지 않았고 PCD에는 접속·적용하지 않았다.

130개 단위/회귀 테스트·typecheck·db:check와 격리 PG18 계약 검증(1 pass / 0 fail / 0 skip)을 통과했다. 테스트 전용 writer의 key 잠금·expected revision·최종 검증·rollback을 확인했으며 실제 tem writer를 검증한 결과는 아니다. 실제 DCD 연결 production 빌드와 개발 3001·standalone 3107의 HTTP 26개 검증도 통과했다. 런타임마다 미공개 순위 HTML 10개(200), 미공개 CSV 2개(404), 빈 검색 JSON(200, `[]`)을 확인했다. 개발 3001은 재시작 후 정상 구동 중이다. `pnpm test:db`는 PG18과 지원 Node가 필수이며 숨은 skip을 통과로 기록하지 않는다. 실제 tem 원천 수집·공식 계산 결과와 CD의 통합은 아직 미검증이다.

## 문서와 코드의 기준

- 제품 목적과 범위는 사용자가 밝힌 의도를 기준으로 한다. 후속 제안은 채택된 결정과 구분한다.
- 구현·버전·배포 설정은 실제 소스, `package.json`, lockfile, workflow를 기준으로 재확인한다.
- 실제 업무 DB 설치·tem 실행·사이트 데이터 기준일은 별도의 연결·통합 확인이 필요하다. 과거 DAG 조사나 로컬 파일의 존재를 현재 운영 성공으로 해석하지 않는다.
- 문서의 소스 링크는 파일 상대경로다. 라인 번호는 조사 시점의 위치이며, 후속 변경 뒤에는 함수명·설정 키를 함께 확인한다.
- `../../dag/...` 링크는 `silla/cd4`와 `silla/dag`를 형제 디렉터리로 둔 로컬 작업 환경을 전제로 한다. cd4만 clone한 환경에서는 별도 DAG checkout을 연결한다.

## 별도 채팅의 시작 문맥

> `docs/README.md`와 최신 CD → tem 저장 계약 v2·PostgreSQL 18 설치 안내·검증 기록부터 읽는다. cd4는 한국 주식의 숫자와 순위를 보여주는 조회 서비스다. 신규 빈 DCD `192.168.50.27:25433/dcd`에 0000 → 0001 → 0002를 설치하고 실제 DCD 연결 빌드·빈 상태 HTTP 검증을 완료했다. 기존 데이터 이전은 수행하지 않았고 PCD에는 접속하지 않았다. DB는 업무키·FK·행 자체 CHECK를 담당하며, tem이 결과 묶음을 검증하고 값과 완료 헤더를 한 트랜잭션에 기록하면 CD는 공개된 결과를 표시한다. tem 실제 적재·계산 통합과 배포 확인은 설치·격리 테스트와 구분한다. 과거 DAG/Next.js 조사 문서는 해당 날짜의 구조와 판단 근거로 읽고, 현재 구현의 기준은 최신 계약과 소스다.
