# UI·Impeccable Rules

적용: `components/**`, `hooks/**`, `app/**/*.tsx`, `app/globals.css`, CSS modules,
디자인 토큰·브랜드 자산 및 UX/UI 설계·구현·검토. 화면을 바꾸지 않는 서버 작업에는 적용하지 않는다.

## 맥락과 도구

- [PRODUCT.md](../../PRODUCT.md), [DESIGN.md](../../DESIGN.md), 대상의 실제 화면·CSS·컴포넌트,
  관련 `.impeccable/` surface brief를 읽는다. 날짜별 승인과 시안·구현·검증 상태를 구분한다.
  이 파일들의 진행 중인 사용자 수정이나 미확정 선택을 임의로 덮어쓰지 않는다.
  context가 고른 오래된 surface brief가 최신 사용자 결정과 충돌하면 최신 PRODUCT·DESIGN과
  해당 결정의 brief를 우선하고 충돌을 보고한다. 과거 brief를 자동으로 갱신하지 않는다.
- 사용 가능한 `impeccable:impeccable`(또는 동일 Impeccable 스킬)의 `SKILL.md`를 먼저 읽는다.
  세션의 스킬 목록에서 실제 위치를 찾는다. 캐시 버전·전역 경로를 프로젝트 설정으로 고정하지 않는다.
- 해당 SKILL.md가 있는 디렉터리의 `scripts/impeccable context --target <대상 경로>`를
  저장소 루트에서 세션당 한 번 실행한다. 작업에 맞는 playbook을 읽고,
  UI 편집 직전 `reference/craft-floor.md`를 읽는다.
- 검토에는 스킬이 제공하는 critique/audit 등 해당 playbook을 선택한다.
  런처/스킬에 접근할 수 없으면 실행하지 못했음을 알리고 PRODUCT·DESIGN·기존 화면을 직접 읽는다.
  확인한 로컬 사실과 미검증 화면을 밝히며 Impeccable 검토 완료로 표시하지 않는다.
- context의 drift 경고만으로 init/doctor·전역 설정 변경을 수행하지 않는다.
  새 의존성 설치 없이 기존 `components/ui/`의 shadcn 구성요소와 토큰을 먼저 확인한다.

## 지켜야 할 제품·표현

- 전체 지표 순위 → 기업/종목 상세 → CSV 동선을 보존한다.
  기존 브랜드 이름·원본 별·현재 승인된 기록실 스타일과 반응형 헤더를 따른다.
  현재 방향의 원본은 PRODUCT·DESIGN이며 과거 오피스 팔레트·다크 기본값이 이를 덮지 않는다.
- 최초 테마는 기기 설정, 수동 선택은 유지한다. 라이트/다크 모두 읽기·대비를 확인한다.
  금융 상승은 빨강, 하락은 파랑, 순위 이동은 주가 등락과 구분하는 중립 표현을 유지한다.
  실제 색상은 현행 토큰을 재사용한다.
- 모바일 우선 가독성, 작은 화면의 중첩 카드 방지, 표/목록의 순서·단위·숫자 정렬,
  키보드 탐색·접근성 이름·포커스·명도 대비를 지킨다. 모션은 필요한 transform/opacity 위주다.
- 값·기준일·선택 종목·상장 기간을 함께 유지한다. 0/음수와 결측, 현재값과 마지막 제공값을
  구분하며 자세한 기준은 [데이터 Rules](data-temporal.md)를 따른다.
- 실제 공유 성공/실패, 전체 범위 CSV, 검색·최근 기록·탭·페이지 이동을 보존한다.
  내부 구현 설명·샘플 수치·검증되지 않은 실시간/대회 기능을 제품 문구로 넣지 않는다.

## 예외와 확인

- 명시적 재설계 요청은 요청한 영역의 표현을 바꿀 수 있으나 제품 사실·데이터 계약은 유지한다.
  새 시안 선호를 전체 화면 승인·운영 배포 승인으로 확대하지 않는다.
- 구현 후 모바일/데스크톱과 두 테마를 한 번에 브라우저로 확인하고 발견된 문제를 묶어 수정한다.
  필요하면 한 차례 더 확인한다. 핵심 흐름·빈/오류/로딩 상태·가로 넘침·콘솔을 점검한다.
- 테스트 통과와 스크린샷 파일의 존재만으로 UI 완료를 선언하지 않는다.
  [검증 Rules](verification.md)와 [L2·L3](../learnings.md)에 따라 검증 대상·결과·제한을 기록한다.
