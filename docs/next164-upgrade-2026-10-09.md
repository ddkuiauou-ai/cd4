## 성능 개선 적용

[Next.js 16.4 공식 발표](https://nextjs.org/blog/next-16-4)에 따르면 Turbopack 디스크 캐시는 압축·compaction 개선으로 별도 설정 없이 20–25% 줄어든다. 서버 HMR의 지연 컴파일, 공유 runtime chunk, export 이름 축약과 짧은 CSS Module class 이름도 자동 적용된다. 이는 릴리스 전체의 개선 설명이며 이 프로젝트의 실측 개선율은 아니다. 작업 시작 시 `.next`가 없어 같은 조건의 캐시 크기·빌드 속도 전후 비교는 수행하지 않았다.

설치된 16.4 문서를 읽고 `next.config.ts`의 **개발 단계에만** 다음 실험 옵션을 적용했다. 프로덕션 빌드·서버에는 포함되지 않으며 생성된 서버 설정에서도 확인했다.

- [`turbopackGc: true`](https://nextjs.org/docs/app/api-reference/config/next-config-js/turbopackGc): 사용하지 않는 메모리·디스크 컴파일 작업을 정리한다. 기본 수집 시간과 3일 root TTL을 유지한다.
- [`turbopackLazyDynamicImports: true`](https://nextjs.org/docs/app/api-reference/config/next-config-js/turbopackLazyDynamicImports): 브라우저가 요청하는 시점에 client dynamic import를 컴파일한다. 이 앱의 캔들·PER/BPS/DPS 히트맵·분포 차트 7개 모듈을 실제 브라우저에서 확인했다. 일부 `next/dynamic` 대상은 여전히 미리 컴파일될 수 있다.
- [`turbopackPluginRuntimeStrategy: 'workerThreads'`](https://nextjs.org/docs/app/api-reference/config/next-config-js/turbopackPluginRuntimeStrategy): 개발 중 PostCSS 등 Node 도구의 별도 프로세스·소켓 비용을 줄인다. 현재 프로젝트는 고정된 Node 22를 사용한다.

기존 compiler filesystem cache와 workflow의 `.next/cache/turbopack` 재사용 설정은 유지했다. 금융 DB 조회의 최신성·revision 계약은 변경하지 않았다. Cache Components나 React Compiler의 도입은 별도의 동작·성능 검토가 필요해 이번 버전 업데이트에 섞지 않았다.

[Radix 공식 권장](https://www.radix-ui.com/primitives/docs/overview/introduction)에 따라 관련 패키지를 함께 갱신해 공유 의존성 중복을 줄였다. Slot의 RSC 호환성, 모달 내부 포털·탭 blur·disabled Select와 ResizeObserver 처리 등의 수정이 포함된다. Drizzle 0.45.4는 명시적인 prepared query 수정이지만 현재 앱은 `.prepare()`를 사용하지 않으므로 DB 응답 속도 개선을 주장하지 않는다. shadcn의 CLI 의존성 감소와 아이콘·dotenv 수정도 배포 화면 속도 향상과 구분한다.

기본 Turbopack 빌드는 권한이 허용된 로컬 실행에서 확인했고 Webpack fallback은 사용하지 않았다. 이번 한 번의 컴파일은 7.3초, TypeScript 단계는 33.8초였다. 이전 기록과 입력·캐시·권한 조건이 다르므로 이를 전후 속도 향상 수치로 사용하지 않는다.

Next 내부 `collectSegments()`가 배열 대신 `{ segments, segmentTree }`를 반환하게 되어 기존 사이트맵 테스트의 소비 지점 두 곳만 구조분해로 변경했다. 실제 route handler의 동작과 모든 기존 assertion은 유지했다. `next dev`가 생성한 `AGENTS.md` 제목 수준 변경도 포함한다.

변경 범위는 로컬 패키지·개발 설정·테스트 호환·문서다. 배포나 DB 쓰기·마이그레이션은 수행하지 않았다. 전량 정적 export는 현재 동적 조회 화면에 대해 검증한 배포 방식이 아니다.
