## 정확성과 기능

최종 full 입력을 기존 DB 조회와 대조해 **40개 종목 × 7지표, 12개 기업, 24개 순위 페이지, 8개 CSV**가 일치했다. 이전 표본에서는 전체 199개 순위 페이지 / 18,856행도 표시 DTO를 대조했다. 금융 값·큰 정수·revision·업무일은 정확히 유지했고 감사 시각 표현만 ORM의 밀리초 ISO 형식으로 정규화했다. 파일 렌더링 경로의 DB 조회는 0회이며, export 중 요청 시점 DB 경로를 차단한다. 전체 추출의 실제 쿼리·배치·메모리 수치는 상세 JSON의 input.extraction에 있다.

전체 테스트 **225개 통과**, production 타입 검사 통과. 기존 lint 기준선 **오류 28개·경고 27개**를 유지했고 변경 코드에 새 오류·경고를 만들지 않았다. null·0·음수, 현재값/마지막 제공값, BPS 연말, 회사 관측 구성 변화, 이전 가격 관측·이동평균, 전체 CSV·앞자리 0·BOM·0행·revision 불일치, 요청 공유·실패 재시도를 검증했다.

표본의 데스크톱·모바일 390×844에서 모든 지표·기업/종목·우선주·결측·검색·최근 종목·공유·기간 변경과 뒤로가기·다운로드를 확인했다. 이력 JSON 503을 1회 주입해 기본 사실과 연도별 표 유지 및 재시도 복구도 확인했다. 최종 전체 출력의 정적 서버에서는 표본 밖 종목을 포함한 직접 진입·새로고침·화면 이동·순위 쿼리·별칭·404를 추가 확인했다. 예기치 않은 앱 콘솔 오류나 실패 요청은 없었다.

모든 기대 HTML·canonical·사이트맵·별칭·내용 해시와 정적 HTTP 응답을 검사했다. HTML·JSON·직렬화된 RSC의 공유 자산 참조를 검사하고 JS·CSS·RSC 원본 파일의 해시 보존을 확인했다. 공개 파일 목록은 Next 원본+공유 자산+별칭+호스팅 규칙과 정확히 일치하며, 빌드 입력·환경 파일은 포함하지 않는다. fresh full 입력에서 수정된 dotted-name 별칭 규칙도 확인했다.

현재 실데이터는 krx-all만 공개돼 있다. 다른 공개 scope와 미공개·0행 CSV는 fixture 통합 검증이다. 현재 8개 일반 CSV는 모두 공개 상태다. GET 404 단위 검증을 향후 미공개 CSV 파일의 호스팅 HTTP 404 보장으로 확대하지 않는다. 일반 정적 CSV 주소는 기본 범위를 제공하고, 화면의 scope/revision 검증은 정적 명세와 해시 파일을 사용한다.

## 재현과 전달

`pnpm build:static` → 입력 추출·전체 export·조립·전수 검증, `pnpm verify:static` → 최종 출력 검증, `pnpm preview:static` → DB/Next 서버 없이 out 파일만 제공한다. 같은 소스의 완료된 벤치마크가 있으면 8×2를 자동 적용하며, 새로운 환경에서는 `pnpm benchmark:static`으로 측정한다. 전체 out 폴더의 탐색 파일·공유 자료·헤더를 함께 보존한다.

Netlify의 [디렉터리당 54,000파일 제한](https://docs.netlify.com/deploy/deploy-overview/)과 [ZIP 추출 25,000파일 제한](https://docs.netlify.com/api-and-cli-guides/api-guides/get-started-with-api/)은 서로 다르다. 큰 전체 출력은 폴더 배포 방식으로 사용자가 업로드한다. Legacy Free의 [월 100GB](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-legacy-plans/legacy-pricing-plans/)는 방문자에게 보낸 응답량이며, 출력 크기×월 배포 횟수로 계산하지 않는다. 실제 운영 CDN·청구량 확인과 데이터 프리징·자동 스케줄링은 사용자 작업 범위다.
