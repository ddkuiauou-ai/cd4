# Learnings

이 파일은 확인된 재사용 교훈의 색인이다. 파일명 자체에 자동 기억 기능은 없다.
[AGENTS.md](../AGENTS.md)의 작업 시작 절차에서 키워드를 검색하고 관련 항목·근거를 읽는다.
사용자 교정·재사용할 실패 원인을 확인하면 **문제 수정 → 해당 검증 → 기록** 순서로 갱신한다.
과거 실수를 추정해 추가하지 않는다. 일회성 진행 상태·PID·전체 로그는 날짜별 보고서에 둔다.

## 기록·정리 방법

각 항목에 아래 여섯 필드와 근거 링크를 짧게 남긴다.
중복은 기존 항목에 합치며, 안정된 행동은 해당 Rules로 승격하고 이곳에 원래 근거를 유지한다.
오래된 항목은 삭제로 맥락을 잃기보다 적용 종료/대체 규칙을 명시한다.
항목이 늘면 영역별 증거 문서로 상세를 옮기고 이 파일에는 검색용 요약만 남긴다.

```text
### L번호 — 검색 가능한 제목
- 발생 조건:
- 잘못된 행동:
- 확인한 원인·근거: (파일/기록 링크와 확인 날짜)
- 다음 행동:
- 적용 범위·예외: (대체/승격된 Rules 포함)
- 검증 상태: (당시 검증 / 이번 재검증 여부 / 남은 범위)
```

## L1 — 조회 오류·원천 최신일을 공개 결과로 오인

- 발생 조건: 랭킹이 비거나 원천 가격보다 기준일이 오래될 때.
- 잘못된 행동: DB 실패를 빈 결과로 캐시하고 대표 종목 가격 날짜를 회사 순위 날짜로 사용했다.
- 확인한 원인·근거: [2026-10-05 수정 기록](ranking-fix-verification-2026-10-05.md)의
  조회 오류 전달·회사 `marketcapDate` 사용·실제 행 갱신 시각 표시 수정과 반례 검증.
- 다음 행동: 오류/정상 0건/미공개를 구분하고 결과 자체의 기준일·공개 헤더/행을 함께 확인한다.
- 적용 범위·예외: 서버 조회·랭킹·CSV. 당시의 300초 TTL과 옛 Temporal 후처리 실행법은 현행 규칙이 아니다.
  행동은 [데이터 Rules](rules/data-temporal.md), [앱 Rules](rules/app-server.md)에 반영했다.
- 검증 상태: 당시 로컬/회귀·DB 대조 성공 기록을 이관했다. 이번에는 문서·현재 조회 계약만 대조했으며 live 갱신을 재검증하지 않았다.

## L2 — 결측·실제 0·종목 선택·값/날짜 쌍

- 발생 조건: 상세·차트·통계에서 희소 이력, 여러 우선주, 결측값을 표시할 때.
- 잘못된 행동: 결측을 0원으로 표시하거나 유효한 0을 통계에서 제외하고,
  이름/종류로 선택해 여러 종목이 강조되거나 다른 시점의 값과 날짜가 결합됐다.
- 확인한 원인·근거: [2026-10-05 계획 대조](ui-plan-conformance-review-2026-10-05.md)의
  null 보존·securityId 전달·값/날짜 helper·`[0,100]` 통계 반례 수정.
- 다음 행동: ID와 선택 기간을 전달하고 같은 관측의 값/날짜를 사용한다.
  유효한 0은 보존하며 NULL·주입된 결측 0·비교값과 구분한다.
- 적용 범위·예외: 금융 UI/DTO/CSV. 반례 fixture를 실제 운영에서 발생한 데이터 오류로 주장하지 않는다.
  [UI Rules](rules/ui.md), [데이터 Rules](rules/data-temporal.md)에 승격했다.
- 검증 상태: 당시 SSR·회귀·브라우저 수정 확인 기록이 있다. 이번 제품 코드/브라우저 재검증은 수행하지 않았다.

## L3 — 테스트·시안 승인과 UI 완료를 구분

- 발생 조건: 승인된 디자인을 구현하고 완료 보고할 때.
- 잘못된 행동: 메인 구조 기준 누락·상세/공유/CSV 미달이 남았는데 전체 완료로 판단했다.
- 확인한 원인·근거: [PRODUCT](../PRODUCT.md)의 사용자 교정 기록과
  [2026-10-05 계획 대조](ui-plan-conformance-review-2026-10-05.md)의 미달·수정·검증 한계.
- 다음 행동: 대상 surface brief/승인 범위를 실제 화면·동작과 대조하고
  테스트 성공·독립 리뷰·사용자 수락·전체 export·운영 배포를 각각 보고한다.
- 적용 범위·예외: UI 완료 판단. 과거 화면 구조를 현재 승인된 디자인보다 우선하지 않는다.
  [UI Rules](rules/ui.md), [검증 Rules](rules/verification.md)에 반영했다.
- 검증 상태: 당시 수정 항목 해결과 제한된 출력 검증 기록만 이관했다. 현재 UI 전체 인수는 미확인이다.
