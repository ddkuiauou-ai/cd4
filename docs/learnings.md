# Learnings

이 파일은 확인된 재사용 교훈의 색인이다. 파일명 자체에 자동 기억 기능은 없다.
[AGENTS.md](../AGENTS.md)의 작업 시작 절차에서 키워드를 검색하고 관련 항목·근거를 읽는다.
사용자 교정·재사용할 실패 원인을 확인하면 **문제 수정 → 해당 검증 → 기록** 순서로 갱신한다.
과거 실수를 추정해 추가하지 않는다. 일회성 진행 상태·PID·전체 로그는 날짜별 보고서에 둔다.

## 기록·정리 방법

각 항목에 아래 여섯 필드와 근거 링크를 짧게 남긴다.
중복은 기존 항목에 합치며, 안정된 행동은 해당 Rules로 승격하고 이곳에 원래 근거를 유지한다.
오래된 항목은 삭제로 맥락을 잃기보다 적용 종료/대체 규칙을 명시한다.
항목이 늘면 영역별 증거 문서로 상세를 옮기고 이 파일에는 검색용 요약만 남긴다.

```text
### L번호 — 검색 가능한 제목
- 발생 조건:
- 잘못된 행동:
- 확인한 원인·근거: (파일/기록 링크와 확인 날짜)
- 다음 행동:
- 적용 범위·예외: (대체/승격된 Rules 포함)
- 검증 상태: (당시 검증 / 이번 재검증 여부 / 남은 범위)
```

## L1 — 조회 오류·원천 최신일을 공개 결과로 오인

- 발생 조건: 랭킹이 비거나 원천 가격보다 기준일이 오래될 때.
- 잘못된 행동: DB 실패를 빈 결과로 캐시하고 대표 종목 가격 날짜를 회사 순위 날짜로 사용했다.
- 확인한 원인·근거: [2026-10-05 수정 기록](ranking-fix-verification-2026-10-05.md)의
  조회 오류 전달·회사 `marketcapDate` 사용·실제 행 갱신 시각 표시 수정과 반례 검증.
- 다음 행동: 오류/정상 0건/미공개를 구분하고 결과 자체의 기준일·공개 헤더/행을 함께 확인한다.
- 적용 범위·예외: 서버 조회·랭킹·CSV. 당시의 300초 TTL과 옛 Temporal 후처리 실행법은 현행 규칙이 아니다.
  행동은 [데이터 Rules](rules/data-temporal.md), [앱 Rules](rules/app-server.md)에 반영했다.
- 검증 상태: 당시 로컬/회귀·DB 대조 성공 기록을 이관했다. 이번에는 문서·현재 조회 계약만 대조했으며 live 갱신을 재검증하지 않았다.

## L2 — 결측·실제 0·종목 선택·값/날짜 쌍

- 발생 조건: 상세·차트·통계에서 희소 이력, 여러 우선주, 결측값을 표시할 때.
- 잘못된 행동: 결측을 0원으로 표시하거나 유효한 0을 통계에서 제외하고,
  이름/종류로 선택해 여러 종목이 강조되거나 다른 시점의 값과 날짜가 결합됐다.
- 확인한 원인·근거: [2026-10-05 계획 대조](ui-plan-conformance-review-2026-10-05.md)의
  null 보존·securityId 전달·값/날짜 helper·`[0,100]` 통계 반례 수정.
- 다음 행동: ID와 선택 기간을 전달하고 같은 관측의 값/날짜를 사용한다.
  유효한 0은 보존하며 NULL·주입된 결측 0·비교값과 구분한다.
- 적용 범위·예외: 금융 UI/DTO/CSV. 반례 fixture를 실제 운영에서 발생한 데이터 오류로 주장하지 않는다.
  [UI Rules](rules/ui.md), [데이터 Rules](rules/data-temporal.md)에 승격했다.
- 검증 상태: 당시 SSR·회귀·브라우저 수정 확인 기록이 있다. 이번 제품 코드/브라우저 재검증은 수행하지 않았다.

## L3 — 테스트·시안 승인과 UI 완료를 구분

- 발생 조건: 승인된 디자인을 구현하고 완료 보고할 때.
- 잘못된 행동: 메인 구조 기준 누락·상세/공유/CSV 미달이 남았는데 전체 완료로 판단했다.
- 확인한 원인·근거: [제품 결정 이력](archive/product-decisions-2026-11-02.md)의 사용자 교정 기록과
  [2026-10-05 계획 대조](ui-plan-conformance-review-2026-10-05.md)의 미달·수정·검증 한계.
- 다음 행동: 대상 surface brief/승인 범위를 실제 화면·동작과 대조하고
  테스트 성공·독립 리뷰·사용자 수락·전체 export·운영 배포를 각각 보고한다.
- 적용 범위·예외: UI 완료 판단. 과거 화면 구조를 현재 승인된 디자인보다 우선하지 않는다.
  [UI Rules](rules/ui.md), [검증 Rules](rules/verification.md)에 반영했다.
- 검증 상태: 당시 수정 항목 해결과 제한된 출력 검증 기록만 이관했다. 현재 UI 전체 인수는 미확인이다.

## L4 — 최근 본 종목의 로컬 중복·식별 기준

- 발생 조건: 브라우저에 같은 종목 코드의 서로 다른 과거 SID가 남거나 시장·경로가 바뀐 뒤 다시 방문할 때.
- 잘못된 행동: 저장은 SID, React key는 시장·코드로 구분하고 검색 목록이 로드된 뒤에만 중복을 정리했다.
- 확인한 원인·근거: 2026-11-01 [최근 기록 유틸리티](../lib/recent-securities.ts)와
  [회귀 테스트](../tests/recent-securities-deduplication.test.cjs)에서 같은 코드·다른 SID의 중복 key를 재현했다.
  같은 종목이 순위와 최근 목록에 각각 나타나는 것은 정상이며 충돌은 각 목록 내부에서 발생한다.
- 다음 행동: [현행 코드당 한 SID 계약](security-lifecycle-contract-2026-10-13.md)에 맞춰 ticker로 읽기·추가·key를 통일한다.
  최신 방문 문맥과 지표별 최신 값을 병합한 뒤 개수를 제한하고, 렌더링 후 변경된 로컬 기록만 저장한다.
- 적용 범위·예외: 최근 본 브라우저 저장소. 검색 요청을 추가하지 않으며, snapshot 읽기는 저장·이벤트를 발생시키지 않는다.
  빈 ticker의 기존 항목은 secCode로 구분한다. 계약 변경 시 식별 기준도 다시 검토한다.
- 검증 상태: Node 22.23.3의 중복 회귀 8개·관련 기존 회귀, 타입 검사·변경 파일 린트 통과.
  StrictMode의 두 목록에서 fetch·콘솔 오류 0건과 삭제 동기화, 저장 실패를 확인했다.
  실제 브라우저의 반복 방문·랭킹 복귀 및 데스크톱 라이트·모바일 다크에서 중복 경고가 없었다.
  전체 린트의 기존 28개 오류는 별개이며 전체 정적 빌드·운영 배포는 수행하지 않았다.

## L5 — 차트 방향 속성과 실제 CSS 색 연결

- 발생 조건: 전일 등락률은 상승·하락을 구분하는데 랭킹 가격 추이는 모두 파랑으로 보일 때.
- 잘못된 행동: 차트의 `data-direction`만 전달하고 CSS의 파랑 고정값을 그대로 두었다.
- 확인한 원인·근거: 2026-11-01 [차트 컴포넌트](../components/ranking-row-parts.tsx)와
  [CSS](../components/ranking-view.module.css)의 방향별 색 연결, [회귀](../tests/ranking-view.test.cjs)로 확인했다.
- 다음 행동: 차트는 저장된 전일 대비, 순위 이동은 이전 순위 대비 방향으로 독립적으로 표시한다.
  속성뿐 아니라 브라우저의 실제 색·끝점 위치·모바일 크기를 확인한다. 반복 강조는 화면 밖·숨겨진 탭에서 멈추고 기본 원을 항상 유지한다.
- 적용 범위·예외: 랭킹의 작은 가격 추이·순위 이동. 최신 관측값이 결측이면 끝점 원을 생략한다.
  0은 결측으로 취급하지 않고 정확한 큰 수와 기존 결측 구간을 보존한다.
- 검증 상태: 관련·정적 랭킹 회귀 34개, 타입 검사·변경 TSX 린트 통과. 실제 메인과 별도 예시에서
  라이트 데스크톱·다크 모바일의 계산된 색과 9×9px 금색 원을 확인했다. 새 요청·타이머는 추가하지 않았다.
  후속 사용자 교정으로 원을 12px·2px 실선으로 강화하고 2.4초 바깥 원 맥동을 적용했다.
  [공유 observer 회귀](../tests/ranking-endpoint-motion.test.cjs)를 포함한 36개 검사와 타입·변경 TSX 린트가 통과했다.
  실제 브라우저에서 동작·스크롤 시 정지·두 테마의 크기와 대비를 확인했다. 추가 데이터 조회·타이머는 없으며
  보이는 끝점의 애니메이션만 작은 클라이언트 컴포넌트가 제어한다.

## L6 — 깜박임의 대상·테두리·끝점 중심 확인

- 발생 조건: 사용자가 금색 원 자체의 깜박임과 차트 끝점 강조를 요청할 때.
- 잘못된 행동: 고정 원에 확대되는 바깥 원을 더해 두 개의 원이 보이게 했으며, 갈색 계열 `brand-ink`를 금색 강조에 사용했다.
  이후 불투명한 배경으로 차트 끝을 가렸고 ‘실선’이라는 단어를 사용자의 선·공간 예시보다 우선했다.
- 확인한 원인·근거: 2026-11-01 사용자 교정과 [끝점 CSS](../components/ranking-view.module.css)의 별도 `::after`·scale 효과.
- 다음 행동: 용어보다 사용자가 묘사한 모양을 기준으로 삼고, 원 하나의 크기·위치를 고정한다.
  투명한 가운데와 선명한 금색 점선으로 끝점을 보여주며 SVG 마지막 좌표와 원 중심을 실제 픽셀로 비교한다.
- 적용 범위·예외: 이 랭킹 끝점의 사용자 요청 범위. 최신 요청은 끝부분을 가운데로 보이게 하는 것이므로 이전 불투명 배경 원칙은 폐기했다.
- 검증 상태: 14px·2.5px 네온 금색 점선, 투명한 내부와 12–100% 불투명도 변화를 적용했다.
  데스크톱 라이트·모바일 다크 각 20개 차트에서 마지막 좌표와 원 중심의 오차가 0.01px 미만이었고 콘솔 오류·가로 넘침이 없었다.
  기존 observer 회귀 4개와 diff 검사를 통과했다. CSS 변경 범위여서 타입 검사·전체 회귀는 반복하지 않았다.
  후속으로 큰 선 조각을 2px의 둥근 점으로 바꾸고 행 ID에서 정한 시차·배치 각도를 적용했다.
  무작위 값을 쓰지 않아 SSR·재렌더링의 설정이 일치한다. 관련 회귀 29개·타입 검사·변경 TSX 린트와
  실제 브라우저의 시차·각도 분산, 끝점 중심 유지 확인을 통과했다.

## L7 — 모바일 지표 메뉴의 줄 수와 선택 항목 노출

- 발생 조건: 일곱 지표를 두 행으로 모두 보여주는 구성이 모바일에서 순위 본문을 밀어낼 때.
- 확인한 원인·근거: 2026-11-01 사용자 요청에 따라 기존 두 행 결정을 한 줄 가로 스크롤로 변경했다.
  [메뉴](../components/market-nav.tsx)와 [반응형 CSS](../components/ranking-view.module.css)에 반영했다.
- 다음 행동: 메뉴 안에서만 스크롤하고 항목을 축소·줄바꿈하지 않는다. 진입·지표 변경·폭 변경 때
  가려진 선택 항목만 드러내며, 사용자가 직접 움직인 메뉴와 페이지의 세로 위치를 보존한다.
- 적용 범위·예외: 랭킹의 일곱 지표 메뉴. 상세의 기본 정보 포함 여덟 지표 메뉴는 별도 규칙을 유지한다.
- 검증 상태: 관련 회귀 36개·타입 검사·변경 TSX 린트 통과. 실제 320px·390px에서 한 줄·44px 터치 높이,
  좌우 스크롤·지표 이동·선택 항목 노출·세로 위치 유지·문서 가로 넘침 없음을 확인했다.
  1280px에서 일곱 메뉴가 모두 보이고 콘솔 오류·경고가 없었다. 전체 정적 빌드·운영 배포는 수행하지 않았다.

## L8 — 반응형 시안은 중간 폭의 공간 배분부터 확인

- 발생 조건: 많은 정보를 유지하면서 랭킹의 화면 폭 활용도를 높이는 시안을 만들 때.
- 잘못된 행동: 차트를 넓게 보여줄지 정보를 촘촘히 쌓을지의 선택으로 문제를 좁히고,
  본문 600px에서 전체 행을 두 층으로 바꿔 500px 안팎의 가운데 공간이 비게 했다.
- 확인한 원인·근거: 2026-11-01 사용자 교정. 사용자는 차트 중요도 선택이 아니라 모든 폭에서
  정보와 차트가 가용 공간을 균형 있게 나눠 쓰는 것을 요청했으며, 제품 구현 전 시안만 다시 요청했다.
- 다음 행동: 순위·식별·주 지표·주가의 최소 읽기 폭과 공통 정렬선을 먼저 정한다.
  식별·주 지표에는 적정 폭과 상한을 두고 남는 폭은 차트에 배분하며, 여백·차트 크기를 연속적으로 조절한다.
  정보 묶음 내부부터 접으며 전체 행 재배치는 실제 최소 폭에서만 검토한다.
  창이 넓어질 때 패딩·레일·배치 전환 때문에 차트나 본문이 갑자기 작아지지 않는지도 확인한다.
- 적용 범위·예외: 랭킹 반응형 설계·시안 검토. 같은 폭에서 모든 열을 같은 너비로 만들라는 뜻은 아니다.

- 검증 상태: 독립 시안에서 중간 폭·데스크탑 잔여 폭·두 테마와 긴 이름/큰 숫자/결측을 확인했다.

## L9 — 넘침 검사와 실제 글자 정렬 검사를 구분

- 발생 조건: 반응형 시안에서 폭이 작아지면 이름·코드·값이 세로로 쌓일 때.
- 잘못된 행동: 부모 박스의 넘침과 열 너비를 확인한 뒤, 같은 묶음의 실제 글자 시작점도 맞는 것으로 판단했다.
  넓은 폭에서 차트·종가·등락률을 가로로 펼치는 요청도 주가 묶음을 계속 세로로 두면서 놓쳤다.
- 확인한 원인·근거: 2026-11-01 후속 사용자 교정을 앱 내 브라우저의 320px 시안에서 재현했다.
  이름 묶음에 세로 flex와 기존 `flex-wrap:wrap`·`align-content:center`가 함께 남아
  이름·코드가 시총보다 약 34px 오른쪽으로 이동했다. 화면 밖 넘침은 없어도 같은 종목의 정렬이 틀릴 수 있었다.
- 다음 행동: 쌓인 식별 정보의 정렬을 명시하고, 값 텍스트를 독립 요소로 감싼다.
  부모 박스와 함께 `Range.getBoundingClientRect()`로 이름·코드·값의 실제 시작점, 상하 순서,
  행 내부 포함 여부를 비교한다. 최대 폭의 가로 배치와 중간 폭의 스택도 각각 관찰한다.
- 검증 상태: 독립 시안의 왼쪽 정렬 grid와 실제 글자 좌표를 확인했다.

## L10 — 작은 차트의 오버레이는 선분·끝점·최소 높이를 함께 확인

- 발생 조건: 좁은 순위 행에서 종가·차트·등락률을 같은 영역에 배치할 때.
- 확인한 원인·근거: 2026-11-01 사용자 교정으로 넓은 화면은 합산 시총 → 종가 → 등락률 → 차트,
  좁은 화면은 종가 → 차트 → 등락률 순서를 독립 시안에 반영했다. 숫자 순서만 바꾸면 실제 차트 높이는 확보되지 않는다.
- 다음 행동: 위쪽 종가·아래쪽 등락률의 읽는 순서를 유지하고, 우측 우선·좌측 대안의 두 후보만 검사한다.
  관측점뿐 아니라 연결 선분 전체, 끝점 원의 반경과 여유를 글자 사각형과 비교한다.
  후보가 모두 겹치면 위아래 글자 공간을 확보하고 중앙에 그리며, 선의 가용 높이를 최소 30px 유지한다.
  횡보는 중앙 수평선으로 처리하고, 폰트 로딩·폭 변경 후 다시 측정한다. SVG와 글자 치수는 같은 좌표계로 환산한다.
- 적용 범위·예외: 별도 배치 시안의 가상 추이. 이번 예시는 상승·하락·횡보·급등락·V자이며 실제 금융 데이터 검증을 대신하지 않는다.
  오버레이 위치가 종목마다 달라지는 비교 편의성과 안전 배치의 세로 비율 차이는 시안 검토 대상이다.
- 검증 상태: 독립 시안의 상승·하락·횡보·급등락·V자에서 글자/선분/끝점의 충돌과 최소 선 높이를 확인했다.
  시안 경계·치수는 [시안 측정 기록](archive/ranking-mock-review-2026-11-01.md)에 보존한다.

## L11 — 절대 배치한 숫자의 폭은 이전 위치에 의존하지 않게 한다

- 발생 조건: 좁은 주가 영역에서 측정한 글자 폭으로 `left`를 정하고 화면 폭을 연속 변경할 때.
- 확인한 원인·근거: 2026-11-02 실제 standalone 검사에서 `width:auto`인 절대 배치 숫자가
  이전 `left` 뒤의 남는 폭에 맞춰 줄바꿈되어, 다음 측정의 높이가 커졌다. 넘침·충돌이 없어도 행이 과하게 늘어날 수 있었다.
- 다음 행동: 숫자에 고유 폭(`width:max-content`)과 영역 상한(`max-width:100%`)을 함께 둔다.

- 검증 상태: 연속 폭 변경 후 행·차트의 실제 크기와 글자/선/끝점, 두 테마 및 주요 이동·CSV를 확인했다.
