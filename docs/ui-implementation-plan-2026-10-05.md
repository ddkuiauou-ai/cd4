# 황금 전광판 UI 구현 계획

2026-10-05 · 사용자 승인 계획에 따른 제품 코드 구현 및 검증 단계.

Impeccable `shape`에 따라 사용자 결정, 최종 시안, 실제 소스의 제약을 연결했다. 사용자 지적 후 계획 대조에서 메인 정보 구조와 일부 상세·공유·다운로드 계약의 미달을 확인해 수정했다. 새 독립 리뷰에서 메인의 계획 부합을 확인했고, 후속 상세 수정 네 항목도 resolved 판정을 받았다. 이 판정은 전체 인수 기준 통과나 사용자 수락을 의미하지 않는다. 전체 정적 출력과 실제 운영체제·글자 확대 환경의 검증은 남아 있어 전체 완료 판정을 보류한다. 디자인 규칙은 `DESIGN.md`, 검증 결과와 환경 제약은 [구현 검증 기록](./ui-implementation-verification-2026-10-05.md)에 남긴다.

**최신 후속 구현:** [인수 기준 대조표](./ui-plan-acceptance-check-2026-10-05.md)에서 발견한 R1–R5를 수정했다. 최종 테스트 175/175·타입·standalone 334/334와 수정 화면 확인을 마쳤다. [후속 구현 기록](./ui-plan-completion-2026-10-05.md)에 상세 결과와 증거를 남겼다. 전체 export·lint·실제 환경의 남은 검사 때문에 전체 계획 인수 완료로 기록하지 않는다.

## 1. 구현할 경험과 기준 시안

개인 투자자가 검색엔진에서 지표별 전체 순위에 직접 들어오고, 기업·종목 상세로 이동하고, 엑셀에서 사용할 데이터를 내려받는 경험이 중심이다. 사이트 안의 검색은 기존처럼 기업·종목 상세로 연결한다. 화면의 모드는 **Operate**다. 브랜드의 재미는 로고와 금색 강조에 담고, 표·차트·탐색에서는 숫자의 의미와 스캔 속도를 우선한다.

| 확정된 방향 | 구현 결과 |
| --- | --- |
| ‘천하제일’ + 기존 별 SVG + ‘단타대회’ | 실제 나눔명조 ExtraBold 800 텍스트와 원본 `public/icon.svg`를 조합한다. 작은 화면에서도 전체 이름을 유지한다. |
| A ‘황금 전광판’ | 빨강·금색 브랜드, 큰 순위, 간결한 행 구분, 정보 밀도 있는 표를 사용한다. |
| 라이트 본문·헤더는 화이트 | 모바일·데스크톱에서 같은 흰색을 사용한다. 우측 패널만 아주 옅은 중립 회색으로 나눈다. |
| 데스크톱은 본문 + 공통 우측 패널 | 최근 본 종목을 패널 최상단에 두고, 랭킹과 상세에서 같은 위치·간격·표면을 공유한다. |
| 메인 / 랭킹과 7개 지표 탐색 | 전역 메뉴, 전체 순위 지표 메뉴, 현재 기업·종목의 상세 지표 메뉴를 구분한다. |
| 순위 변화 | 데스크톱은 현재 순위 옆, 모바일은 같은 중심축의 한 묶음. 주가 등락과 다른 중립색으로 표시한다. |
| 첫 방문은 기기 설정을 따름 | 기존 `next-themes`의 system 기본값을 유지하고 수동 선택을 저장한다. |
| CSV는 현재 선택한 지표의 전체 순위 | 화면의 기업 합산/종목 범위, 모집단, 정렬, 기준일을 유지하고 페이지 제한을 해제한 데이터를 제공한다. |

시각적 기준은 [최종 비교 화면](http://127.0.0.1:49673/white-shell.html?theme=light)과 저장된 [라이트 비교 캡처](../.impeccable/logo-review/review/white-shell/comparison-light.jpg), `review/white-shell/`의 두 테마 캡처다. 로컬 서버가 꺼져도 저장된 캡처와 [표면·순위 규칙](./white-shell-refinement-2026-10-05.md)을 기준으로 구현할 수 있다.

PNG는 구도·분위기의 근거다. 시안의 예시 날짜, 6개 행, ‘다음 20개’, 미세 텍스처, 절대 좌표는 제품 규칙이 아니다. 제품은 실제 HTML, CSS Grid/Flex, 데이터, 링크로 만든다. 시안 뷰어의 이미지 배경 위 합성 코드를 제품 컴포넌트로 가져오지 않는다.

## 2. 적용 범위와 먼저 해결할 차이

적용 범위는 전역 헤더·검색·테마·모바일 탐색, `/dashboard` 메인, 7개 지표의 전체 랭킹과 페이지 이동, 기업·종목 상세와 지표별 차트·연도 표, 최근 본 종목, 보통주·우선주 링크, 공유·CSV, 로딩·빈 결과·오류·결측 화면이다.

기존 URL, canonical, 정적 경로, 데이터 수집·캐시 정책, 지표 계산은 유지한다. 회원·포트폴리오·대회 참가·거래 기능은 이 작업에 추가하지 않는다. 광고 영역 신설이나 데이터 최신 집계 작업도 별도 범위다.

| 확인된 차이·사용자 보고 | 이번 구현에서의 처리 |
| --- | --- |
| 랭킹·기업 상세·종목 상세의 셸이 중복돼 있다. | 공통 폭·패딩·헤더·패널 슬롯을 추출한다. 색만 바꾸는 작업으로 끝내지 않는다. |
| 첫 페이지는 20행, 다음 페이지부터 100행인데 모바일 홈은 10행만 보여준다. | 동일 페이지의 모든 행에 기기별로 접근할 수 있게 한다. 기존 페이지 규칙과 URL은 유지한다. |
| `/marketcaps/[page]`는 768–1023px에서 목록이 사라진다. | 표/목록의 전환 기준을 공용화하고 이 구간을 필수 검증한다. |
| 표에서 가격 데이터가 없는 기업을 제외한다. | 유효한 랭킹 행은 유지하고 가격·추이만 ‘—’ 또는 데이터 없음으로 표시한다. |
| 메뉴 경로·명칭이 기기마다 다르고 `/screener`처럼 없는 목적지가 있다. | 실제 메인·랭킹·검색·최근 기능으로 통합한다. 동작하지 않는 버튼이나 가짜 목적지를 만들지 않는다. |
| 시가총액 탭 클릭이 기업 합산에서 종목 범위로 바뀔 수 있다. | 시가총액의 현재 범위를 유지하고, 범위 선택을 URL에 맞춰 제어한다. |
| 최근 기록은 같은 종목의 지표 이동 때 갱신되지 않을 수 있다. | 종목·지표·값 변경을 반영하고, 최근 항목은 마지막으로 본 지표로 돌아가도록 개선한다. 이전 저장값은 호환한다. |
| 상세의 마지막 순위에서 이전 이동도 사라질 수 있다. | 이전·다음 링크의 경계를 각각 판단한다. |
| 고정 헤더·레일·앵커의 offset이 서로 다르다. | 측정한 헤더 높이와 공통 간격을 공유한다. |
| 사용자가 운영 화면에서 라이트/다크 전환 시 우측 상단 테마 아이콘의 정렬이 깨진다고 보고했다. | 구현 전에 전환 전·중·후를 관찰해 재현한다. 아이콘 중심·버튼 크기·라벨 정렬·주변 헤더 위치를 고정하고 두 테마의 완료 기준에 포함한다. |

데스크톱 상세는 승인된 시안을 따른다. 모바일·태블릿 상세와 메인 전체 구성은 별도 완성 이미지가 없어 같은 디자인 규칙으로 구조안을 먼저 정리해야 한다. 메인은 이 단계를 누락했음을 확인했고, [메인 구조 기준](../.impeccable/surfaces/app-dashboard-page-tsx.md)을 추가해 요약 → 주가 흐름 → 시총 TOP5 순서로 수정했다. 1024px부터 흐름과 TOP5를 두 열에 배치하고, 1280px부터 공통 보조 레일을 사용한다.

## 3. 공통 디자인 규칙

### 표면·색상

색은 브랜드, 액션, 주가, 순위, 오류로 의미를 나눈다. 현재 `primary`와 `destructive`가 가격·순위에도 쓰이므로 금색으로 일괄 치환하지 않는다. 차트의 색 참조도 함께 연결한다.

| 역할 | 라이트 | 다크 | 사용 |
| --- | --- | --- | --- |
| 본문·헤더 | `#FFFFFF` | `#181A1C` | 페이지 기본 표면 |
| 우측 패널 | `#F7F7F7` | `#22292E` | 최근·조회 기준·보조 정보 |
| 경계선 | `#E6E6E6` | `#343A40` | 영역 구분·표 경계 |
| 기본 글자 | `#181A1C` | `#F5F7F9` | 제목·회사명·지표 값 |
| 보조 글자·순위 변화 | `#59636B` | `#CBD1D6` | 코드·날짜·이동량 |
| 일반 순위 | `#66717D` | `#D4DBE1` | 큰 현재 순위 |
| 1위 글자 | `#A26300` | `#F8CD37` | 흰 배경에서도 읽히는 금색 계열 |
| 주가 상승 | `#DC3030` | `#F06A68` | 가격·등락률·관련 차트 |
| 주가 하락 | `#1D5FBF` | `#77A9FA` | 가격·등락률·관련 차트 |
| 브랜드 | 금색 `#F8AD02`, 빨강 `#DC3030` | 동일 원본 계열 | 로고·별·주요 액션·활성 지표 |

화이트 본문·옅은 레일·브랜드 색은 시안과 사용자 결정에서 가져왔다. 다크 세부색과 데이터 색은 그 방향 안의 구현 초안이며 실제 차트·작은 글자 대비로 확정한다. 흰 배경의 작은 금색 글자는 별도 가독성 색을 사용한다. 오류는 별도 의미 토큰을 사용해 주가 하락과 혼동하지 않게 한다.

활성 Tailwind 4 경로인 `app/globals.css`의 CSS 변수와 `@theme inline`에서 관리한다. 현재 로드되지 않는 구형 `tailwind.config.js`에만 값을 추가하지 않는다. 새 셸에 적용되는 유색 배경·그라데이션·큰 카드 그림자는 정리하되, 관계없는 파일의 미사용 스타일 청소로 작업을 넓히지 않는다.

### 글자·로고·간격

- 로고는 로컬 WOFF2 + SVG. 검토용 나눔명조 파일은 18,040B, 별은 767B다. `next/font/local`로 옮기고 OFL·출처를 함께 보존한다. 별도 재서브셋을 만들면 reserved-name 조건도 확인한다. 기존 전체 SVG 로고보다 항상 작다고 주장하지 않는다.
- 나눔명조는 로고에만 적용한다. 본문은 명시적인 한국어 시스템 sans 스택을 쓰고, 숫자는 `tabular-nums`로 정렬한다. 로고 외 Noto Serif 사용을 확인한 뒤 외부 Google Fonts 링크를 정리한다.
- 초기 타입 규칙: 본문 14–16px, 보조 12–14px, 모바일 화면 제목 24px, 데스크톱 제목 32px, 구역 제목 18–21px. 로고는 데스크톱 약 28–30px, 모바일 약 22–24px에서 시작해 320px의 전체 이름을 검증한다.
- 간격은 4/8/12/16/24/32px 단계로 정리한다. 행·버튼 크기는 내용과 실제 터치 영역에 따라 정하고 시안 이미지의 배율을 그대로 쓰지 않는다.
- 버튼은 금색 주요 액션, 중립 보조 액션, 텍스트 링크의 세 역할로 제한한다. 작은 링크 행도 명확한 hover·focus·선택 상태를 제공한다.

### 테마 전환 컨트롤의 정렬

점검 대상은 우측 상단 `components/mode-toggle.tsx`와 `site-header.tsx`의 버튼 배치다. 구현 전 브라우저에서 기존 버튼 폭이 라이트 89.53px, 다크 77.42px로 변하고 아이콘 중심도 달라지는 현상을 확인했다. 해·달 아이콘의 서로 다른 흐름과 가변 버튼/라벨 폭을 공통 고정 슬롯으로 교체했다. 구현 후 1440px에서는 두 테마 모두 버튼 96×40px, 390px에서는 40×40px이며 아이콘 슬롯과 인접 검색창의 위치도 동일했다.

구현 규칙:

- 두 아이콘은 동일한 고정 크기 슬롯에서 같은 중심에 겹친다. Grid의 같은 셀 또는 명시적인 inset을 사용하고 아이콘별 흐름/좌표 차이를 없앤다.
- 같은 화면 너비에서는 테마가 바뀌어도 버튼 외곽 크기와 위치가 유지된다. 라벨 영역은 가장 긴 라벨을 담는 공간을 확보하고 아이콘·라벨 간격을 고정한다. 반응형 아이콘 전용 표시에서도 터치 영역과 중심을 유지한다.
- 전환 효과는 슬롯 내부의 opacity·색상 등으로 제한한다. 버튼 전체의 확대나 다른 너비의 요소 교체로 검색창·내비게이션을 밀지 않는다. 필요하면 아이콘 transform도 제거해 안정적인 정렬을 우선한다.
- 초기 system 적용, hydration, 저장된 테마로 재방문, 실행 중 기기 설정 변경에서도 같은 슬롯을 유지한다. 라이트/다크 표시와 메뉴의 system 선택 상태를 구분하고 기존 테마 저장 동작을 보존한다.
- 드롭다운은 버튼 우측에 안정적으로 붙고 열기/닫기·선택 뒤 포커스 복귀가 동작한다. hover·focus·메뉴 열림·연속 전환에서도 아이콘이 떠 있거나 두 개가 동시에 보이지 않는다.

검증은 라이트 → 다크 → 라이트, system 선택 후 기기 테마 변경, 저장된 테마로 새로고침을 포함한다. 전환 전·중·후 버튼/아이콘 슬롯/라벨/인접 검색창의 bounding box와 중심을 비교해 같은 viewport에서 레이아웃 이동이 없는지 확인한다. 회전하는 SVG 자체의 순간 외곽 대신 고정 슬롯의 중심을 기준으로 삼고, 아이콘의 시각적 중앙도 함께 관찰한다. 데스크톱 헤더와 모바일에서 실제 노출되는 테마 메뉴를 모두 확인한다.

| 320–767px | 간결한 목록. 순위 묶음 → 기업명/코드 → 지표 값/작은 추이 → 등락. 지표는 가로 스크롤 또는 접근 가능한 더보기. | 단일 열. 요약 → 로컬 지표 메뉴 → 차트·기간 → 연도 표·종목 연결. 최근 정보는 상단 ‘최근 본’ 버튼에서 펼친다. |

초기 컨테이너는 최대 1600px, 모바일 좌우 16px, 큰 화면 24–32px 패딩, 본문/레일 간격 24–32px로 잡는다. 본문은 `minmax(0, 1fr)`로 줄어들 수 있게 한다. 이는 구현 출발값이며 1280/1440/1920px에서 실제 표 밀도와 차트 폭을 확인해 확정한다.

모바일에서도 메인/랭킹, 검색, 테마, 모든 지표에 접근할 수 있어야 한다. 현재 하단 메뉴는 실제 목적지 중심으로 정리하고, 고정 영역이 마지막 행·공유·키보드 포커스를 가리지 않도록 safe-area와 하단 여백을 맞춘다. 상세에서 로고를 회사명으로 바꾸는 기존 동작은 새 고정 기업 요약과 중복되지 않도록 구조안에서 판단한다.

데스크톱 본문은 문서 스크롤, 레일은 공통 offset 아래 sticky + 사용 가능한 높이 내의 기본 `overflow-y: auto`를 사용한다. 기존의 전역 wheel 감시와 페이지 끝 `preventDefault`로 레일을 움직이는 방식은 제거한다. 본문 위 스크롤이 갑자기 레일로 넘어가지 않게 하고 트랙패드·키보드·짧은 viewport도 검증한다.

### 순위 묶음

데스크톱은 큰 순위 옆에 작은 수직 화살표와 절댓값을 둔다. 모바일은 현재 순위와 이동량을 하나의 flex 그룹 안에 두고 같은 중심축으로 정렬한다. 전체 그룹은 행의 중앙에 놓고 회사명 영역을 침범하지 않는다.

변화량은 `priorRank - currentRank`. 변화 0은 ‘유지’, 비교 정보가 없으면 이동량을 생략한다. 전일 대비·새 진입·투자 수익이라는 의미를 추가하지 않는다. 툴팁 설명은 ‘이전 4위 → 현재 2위 · 2계단 상승’처럼 제공하며 hover·focus·탭·Escape로 접근한다. 화면 낭독기에도 방향과 변화량을 텍스트로 전달한다.

1–4자리 순위, 큰 이동량, ‘유지’, 비교값 없음, 200% 글자 확대를 검증한다. 모바일은 약 26px 순위와 12px 변화량에서 시작하되 자릿수에 따라 22/18px로 조정하거나 열 폭을 늘린다. 원본 값은 줄이거나 반올림하지 않고, 좁은 곳의 축약은 보조 설명에 정확한 값을 남긴다.

서버 페이지가 기존 조회 결과를 화면용 데이터로 정규화하고, 공통 뷰가 표시한다. DB 모델을 새로 설계하는 작업은 아니다. 현재 Client Component도 초기 HTML을 만들지만, 전체 화면을 큰 client 경계로 묶지 않고 차트·검색·최근·테마·툴팁 등 필요한 부분에만 상태를 둔다.

랭킹 행에는 `scope`, metric, 실제 상세 URL, 현재/이전 순위, 기업·종목 ID, 이름·코드·거래소, 원본 지표 값·단위, 가격·추이의 결측 상태를 명시한다. 목록에는 전체 개수, 현재 페이지, 표시 범위, 총 페이지, 지표 기준일과 가격 기준일을 분리해 전달한다. 첫 행의 `securityId` 유무로 전체 목록의 종류를 추측하지 않는다.

컴포넌트 이름은 작업 중 기존 명명과 맞출 수 있다. 한 화면의 모든 차이를 처리하는 거대한 옵션 컴포넌트는 피하고, 공통 구조와 metric별 chart/table/summary 슬롯을 둔다.

보존할 데이터 의미:

- 기업 시총은 합산값이고 가격·추이는 대표 보통주의 값이다. 종목 시총과 PER/PBR/EPS/BPS/DIV/DPS는 해당 종목 값이다. 라벨로 이 차이를 알린다.
- 상세 view model에 현재 snapshot, history 끝값, 각 기준일과 기간 계산 기준일을 명시한다. 회사 합산의 현재값은 기존 함수처럼 유효한 snapshot을 우선하고 history로 대체한 경우를 구분한다. 요약·레일·구성 차트에서 같은 ‘현재’ 의미의 값은 같은 출처를 사용하거나 다른 시점임을 알린다. 기존 레일의 실행일 기준 기간 계산을 무심코 새로운 계산으로 바꾸지 않고 차트와 공유할 기준을 먼저 정리한다.
- 회사 합산 링크는 현재 metric과 관계없이 `/company/{대표코드}/marketcap`으로 간다. 특정 보통주·우선주는 `/security/{실제코드}/{현재metric}`을 유지한다. 없는 회사 PER/PBR 경로를 만들지 않는다. 선택은 증권 ID 기준으로 표시하고 여러 우선주를 모두 같은 선택으로 강조하지 않는다.
- 실제 0, 음수, `null`, 조회 실패를 구분한다. formatter의 `if (!value)`를 그대로 재사용하지 않는다. 기존 합산 함수가 넣은 0을 UI에서 임의로 결측으로 다시 해석하지 않는다.
- 연간 EPS 변화율은 전년 값의 절댓값을 분모로 사용한다. 연간 표의 지표별 계산을 일반화하면서 의미를 바꾸지 않는다.
- 랭킹 페이지는 첫 20행/이후 100행의 규칙을 유지한다. 페이지별 실제 시작·끝 순위와 다음 페이지 크기로 안내 문구를 만든다. 클라이언트 더보기만으로 전체 접근을 대체하지 않는다.
- 차트 선택 기간·모드, 기업 합산/개별 구성, 가격·재무 지표 기준일을 유지한다. 테마 변경·크기 변경 뒤 차트가 다시 올바른 색과 축으로 그려져야 한다.

## 5. 순서와 단계별 완료 기준

### 0 — 구현 기준과 기준선

현재 작업 트리와 다른 작업의 변경을 기록한다. `pnpm test`, `pnpm typecheck`, `pnpm lint`의 기준선을 확인하고 오류를 기존/이번 변경으로 구분한다. 기존 [메인 검증 문서](./main-recovery-verification-2026-10-05.md)에 타입 오류가 기록돼 있지만 현재 상태를 다시 확인하기 전까지 같은 결과라고 단정하지 않는다.

이 계획과 사용자 결정을 `DESIGN.md` 및 랭킹·상세·메인 surface brief로 옮긴다. 모바일 상세/태블릿/메인의 정보 순서, 좁은 화면의 최근·테마 메뉴, 데이터 없음 상태를 같은 디자인 규칙으로 정리한다. 지표·scope·URL·페이지 범위·다운로드의 계약을 고정한다.

**완료:** 화면별 적용 목록, 디자인 토큰, 링크·단위·기준일 계약, 검증 기준선이 문서화돼 있다. 기준선 오류를 무시 설정으로 숨기지 않는다.

### 1 — 공통 기반

로컬 로고 폰트·별 SVG, Tailwind 4 토큰, 액션·포커스·글자 규칙을 적용한다. 공통 셸·헤더·전역 메뉴·지표 탐색을 구성하고 system/light/dark 전환을 연결한다. 우측 상단 테마 아이콘의 사용자 보고 현상을 먼저 재현하고 고정 슬롯·라벨 영역으로 정렬을 개선한다. 한 헤더 높이 측정값을 레일·sticky·scroll-margin에서 공유한다.

**완료:** 320/390/768/1024/1280/1440px에서 전체 로고와 실제 탐색이 동작한다. 두 테마의 본문/레일 톤이 일치하고 hydration 오류·가로 넘침·중첩 헤더가 없다. 기기 설정 변경과 수동 테마 저장이 일관된다. 반복 전환·초기 적용·새로고침·hover/focus/메뉴 선택에서 테마 아이콘의 중심, 버튼 크기, 라벨 정렬과 인접 헤더 위치가 유지된다.

### 2 — 시가총액 랭킹 한 흐름 완성

기업 합산 `/` 및 `/marketcaps`, 종목 `/marketcap`, 각 페이지 이동을 먼저 적용한다. 공통 행 데이터, 큰 순위/중립 이동량, 데스크톱 추이 열, 모바일 값 아래 추이, 범위 선택, 최근 레일, 조회 기준, 전체 순위 CSV를 연결한다. 첫 페이지의 모든 20행을 모바일에서도 제공한다.

**완료:** 두 scope와 모든 페이지에서 실제 순위가 끊기지 않고 표·목록·CSV 범위가 계약에 맞는다. 가격 누락 기업이 사라지지 않는다. 첫·중간·마지막 페이지, 768–1023px, 순위 경계 상태를 확인한다.

### 3 — 기업·종목 상세 한 흐름 완성

삼성전자 같은 대표 기업을 기준으로 회사 합산 상세와 보통주/우선주 상세를 함께 적용한다. 요약 아래 로컬 지표 탭, 공통 최근 레일, 핵심 지표, 섹션 링크, 단일 Link로 된 종목 행, 차트·기간 컨트롤·연도 표를 배치한다. 좁은 화면은 단일 열로 자연스럽게 바뀐다. 기존 공유 버튼이 소비하는 sticky pin 이벤트는 공통 context의 pin 상태로 연결하거나 호환 어댑터를 두고, 같은 상태를 헤더·공유에서 사용한다.

**완료:** 합산과 개별 종목의 값·선택·URL이 맞고, 여러 우선주·가격 없음·지표 없음에서도 탐색이 유지된다. 요약·레일·차트의 현재값과 기준일이 설명 없이 어긋나지 않는다. 차트 resize·테마 변경·기간 전환·앵커 이동·최근 기록·공유·전체 이력 CSV가 동작한다. pin/unpin·종목 이동·너비 변경 때 공유 버튼이 중복되거나 하단 메뉴와 겹치지 않는다.

**중간 확인 지점:** 랭킹과 상세를 실제 데이터로 나란히 비교한다. 시안과 다른 구조나 의미 문제가 있으면 이 단위에서 조정한 뒤 나머지 지표로 확장한다. 동일한 규칙의 반복 적용은 매번 새 디자인 승인 절차를 만들지 않는다.

### 4 — 모든 지표와 메인에 확장

PER → PBR → EPS → BPS → 배당수익률 → 주당배당금 순으로 공통 랭킹과 상세 슬롯을 적용한다. 같은 7개 순서·명칭을 전역과 상세에 공유하고 단위·음수·연도 계산은 지표별로 검증한다. 기본 기업/종목 정보 경로도 새 셸과 연결한다.

`/dashboard`는 기존 메인 역할과 상승·하락·거래량 탭, 검색 진입, 기업 표시를 유지하면서 새 토큰·헤더·컴포넌트를 적용한다. 이미 개선된 로딩/정상 빈 상태/무가격 기업/서로 다른 기준일 표현을 보존한다. 메인에 전체 랭킹 지표 메뉴를 중복 배치하지 않는다.

메인 정보 순서는 제목·서로 다른 기준일 → 요약 4항목(실제 조회 기업 수, 시총 1위, 조회 상위 기업 내 상승/하락 1위) → 주가 흐름 3탭과 시총 TOP 5다. 1024px부터 마지막 두 영역을 본문 안 2열로 두며 모바일에서는 주가 흐름부터 쌓는다. 총수는 모든 너비의 본문에 표시한다. 실제 거래량이 없는 조회 결과에 임의의 기업을 거래량 순위로 넣지 않는다.

**완료:** 모든 대표 경로·페이지·상세·빈 상태에 기존 look이 섞이지 않는다. 지표를 바꿔도 현재 종목과 의미가 유지되고 모바일에서도 7개 지표에 도달할 수 있다.

### 5 — 검증과 인계

영향받은 행동 테스트를 먼저 확인한 뒤 전체 `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`를 실행한다. 기존 지원 범위인 standalone과 `NEXT_OUTPUT_MODE=export`의 배포 제약을 마지막 호환성 검증에 포함한다. DB/빌드 환경 문제와 UI 결함을 구분해 기록한다. 성공하지 않은 검사를 완료로 표시하지 않는다.

대표 화면을 두 테마·desktop/tablet/mobile로 묶어 한 번 검사하고, 발견한 문제를 한 번에 수정한 뒤 한 번 더 확인한다. 새로운 기능 오류가 있으면 해당 흐름을 검증하되 미세 스타일 수정을 무한 반복하지 않는다. Impeccable `audit`의 접근성·반응형·성능 관점과 `critique`의 계층·탐색·브랜드 관점을 사용한다.

**완료:** 아래 인수 기준, 테스트 결과, 화면 캡처, 미해결 항목과 원인이 인계 문서에 기록돼 있다. 현재 로컬 시안 비교 뷰어는 근거 자료로 보존한다. 운영 배포는 이 구현 계획의 완료 조건에 포함하지 않는다.

## 7. 전체 순위 CSV와 계획의 상태

테마는 사용자 답변으로 확정됐다: **첫 방문 system, 수동 선택 저장**.

CSV도 사용자 답변으로 확정됐다: **현재 선택한 지표의 전체 순위**. 시가총액에서는 기업 합산/종목 선택을 반영한다. 현재 소스의 페이지 단위 다운로드를 확장하는 명시적인 기능 변경이다. 상세의 합산·종목별 구성·전체 이력 CSV는 별개로 유지한다. XLSX는 아직 추가하지 않는다.

다운로드 계약은 다음과 같다.

- 행 범위는 화면과 같은 모집단·정렬·동률 처리·기준일이며 페이지 제한만 해제한다. ‘기업 합산 시총’과 ‘종목 시총’, 다른 지표를 섞지 않는다.
- 파일명은 지표·범위·기준일을 포함한다. 열은 현재/이전 순위·이동량, 기업/종목 이름·코드·거래소, 원본 지표 값·단위·기준일을 기본으로 한다. 가격·등락률을 포함하면 대표 종목과 가격 기준일도 분리한다. CSV에 `549조` 같은 화면 축약값만 넣지 않는다.
- 기존 CSV 직렬화를 재사용하고 UTF-8/BOM·인용·쉼표·줄바꿈·결측 처리를 확인한다. 다운로드 버튼 아래는 ‘전체 순위 · 엑셀에서 열 수 있어요’처럼 범위를 알린다.
- 서버 페이지의 초기 payload에 전체 랭킹을 실어 보내지 않는다. 전체 조회와 직렬화를 공용 서버 함수로 두고 다운로드용 경로에서만 수행한다. 최근 가격 history를 전부 가져오지 않고 필요한 필드만 조회한다.
- 페이지 API를 여러 번 호출해 전체 파일을 합치지 않는다. 종목은 지표별 `rankDate`를 한 번 정해 전체 조회하고 행·총수를 함께 산출한다. 회사는 현재 기업 테이블의 동일한 산출 결과를 사용한다. 상장 보통주 존재 조건, 상장폐지 제외, 유효 순위와 지표별 정렬을 기존 목록과 공유한다.
- 고정된 지표·scope별 파일 URL을 사용한다. 기존 `app/search-data.json/route.ts`처럼 요청값을 읽지 않는 `GET` + `force-static`을 우선한다. export에서는 해당 빌드의 현재 데이터로 정적 CSV를 만들고 다음 빌드에서 갱신한다. 서버에서는 기존 300초 재검증 정책과 맞춰 제공한다. 정적 호스트가 런타임 재검증을 한다고 가정하지 않는다.
- 종목 `rankDate`, 기업의 행별 `marketcapDate`, 파일 산출 시각을 구분한다. 현재 기업 테이블에는 과거 기업 순위 스냅샷이 없고, 기존 화면 기준일은 첫 행의 날짜다. 같은 최신 기준일이라 주장하지 않고 필요한 행별 날짜를 파일에 보존한다. 과거 날짜를 지정해 기업 순위를 다시 조회하는 서비스를 추가하지 않는다.
- 파일 산출 결과의 기준 정보와 목록 표시 기준을 공유한다. 서로 다른 시점의 페이지를 합치지 않으며, 오래 열린 화면에서 산출물이 갱신된 경우에는 새 파일의 기준을 알리고 목록 갱신을 연결한다. 같은 snapshot의 화면·파일 비교를 검증한다.
- 관찰할 수 있는 준비/요청 중/오류 상태를 표시한다. 파일 응답 뒤 안내는 ‘다운로드 시작’이며 사용자 디스크의 저장 완료로 단정하지 않는다. 실패 시 빈 파일을 성공처럼 내려주지 않는다. export 모드의 직접 파일 링크와 서버 다운로드는 같은 이름·범위로 보인다.

구체적인 파일 책임은 다음처럼 나눈다.

| 파일 | 책임 |
| --- | --- |
| 신규 `lib/data/ranking-export.ts` | 기존 목록의 조건·정렬을 공유하는 전체 조회와 산출 기준. 페이지 제한·가격 history 조회 제외. |
| 신규 `lib/csv/ranking.ts` | 기존 직렬화 추출, 고정 열 순서, 원본 값·티커 문자열·행별 기준일·BOM. |
| 신규 `app/ranking-data/companies-marketcap.csv/route.ts` | 기업 합산 시총 전체 파일. |
| 신규 `app/ranking-data/securities-{metric}.csv/route.ts` | 7개 지표의 고정 파일 경로. `{metric}`은 파일명을 설명하는 표기이며 요청 query에 의존하지 않는다. |
| 기존 `CsvDownloadButton.tsx`, 각 랭킹 첫/`[page]` 페이지 | 랭킹은 파일 URL, 상세 전체 이력은 기존 data 방식. 같은 지표·scope는 같은 파일에 연결. |

완료 기준은 같은 산출 snapshot의 첫/중간/마지막 페이지에서 동일한 전체 파일, 모든 기기의 같은 행 개수, 선택 범위와 날짜 의미 일치, 0·음수·결측 원본 값 보존, 두 배포 모드의 다운로드 성공이다.

계획 작성 후 사용자 구현 요청에 따라 제품 코드를 수정하고 테스트·타입 검사·빌드·브라우저 검증을 수행했다. 구현 범위와 결과는 [구현 검증 기록](./ui-implementation-verification-2026-10-05.md)에 정리한다. 새로운 장식 이미지를 생성하지 않고 실제 폰트·SVG·표·차트로 구현했다.

Impeccable의 기존 `flat-type-hierarchy` 예외는 실제 브라우저 글자 크기로 입증된 비교 뷰어 한 파일에만 적용돼 있다. 제품 파일로 확대하지 않는다. 이번 구현은 새 제품 finding을 억제하지 않았으며 자동 훅과 별도 디자인 리뷰의 결과를 검증 기록에 남긴다.
