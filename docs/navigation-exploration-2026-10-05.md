# 메인·랭킹 탐색과 보통주·우선주 이동

2026-10-05. 사용자는 데스크톱 순위·상세의 공통 우측 패널 방향을 긍정적으로 평가하고, 보통주·우선주를 큰 버튼 재사용 또는 리스트 중 어떤 방식으로 표현할지 판단하고 빠진 ‘메인 / 랭킹’을 시안에 통합하도록 요청했다. 기존 브랜드·테마·본문 구조는 유지하는 좁은 후속 수정이다. 제품 구현 전 비교 단계다.

## 기존 기능

- `components/main-nav.tsx`: 메인은 `/dashboard`, 랭킹은 `/`와 `/marketcaps`, `/marketcap`, `/per`, `/pbr`, `/eps`, `/bps`, `/div`, `/dps`에 대응한다.
- `components/site-header.tsx`: 데스크톱에서는 로고 다음에 MainNav, 오른쪽에 검색·테마 전환을 둔다.
- `app/dashboard/layout.tsx`: 메인에서는 전체 순위용 MarketNav를 표시하지 않는다.
- `app/(market)/layout.tsx`, `components/market-nav.tsx`: 랭킹에서는 시가총액 등 시장 전체 순위 지표를 선택한다.
- `components/company-financial-tabs.tsx`: 상세의 지표 메뉴는 같은 회사·종목의 지표 상세로 이동한다. 회사 시가총액은 회사 합산 문맥을 유지하고 PER 등은 해당 종목 문맥으로 이동한다.
- `components/simple-interactive-securities.tsx`, `components/card-marketcap.tsx`: 같은 회사의 보통주·우선주를 현재 지표를 유지한 채 전환한다. 현재 종목과 지표 데이터의 유무에 따라 선택·비활성 상태를 판단한다.

현재 MainNav는 회사·종목 상세에 랭킹 선택 표시를 하지 않는다. 이번 시안에서는 상세도 랭킹 탐색 영역으로 이어진다는 정보 구조를 보여주기 위해 랭킹을 강조한다. 기존 동작을 확인한 사실과 새 활성 표시 제안은 구분한다.

## 표현 판단

보통주·우선주는 데이터 표만으로 표현하면 이동 가능한 요소라는 점이 약해진다. 전체 행을 누를 수 있는 작은 링크 버튼을 사용한다. 큰 본문용 카드의 종목 데이터·지표 포맷·경로 계산은 공유하고 본문용과 우측용 크기·정보 밀도를 나눈다. 컴포넌트 재사용을 위해 두 위치에서 같은 크기의 카드를 강제하지 않는다.

우측용 행은 약56–64px이며 회사명, 보통주·우선주 배지, 코드·시장, 현재 지표 값, 오른쪽 이동 표시를 둔다. 기본 상태는 얇은 중립색 윤곽선과 옅은 면, hover·키보드 focus는 행 전체에 적용한다. 종목 화면에서는 현재 ticker인 행만 옅은 금색 선택과 ‘현재’ 표시를 제공한다. 이번 삼성전자 기업 합산 예시는 두 종목 모두 미선택이다. 합산549조를 보통주494.3조와 같은 선택으로 보이게 하지 않는다.

구현 시 하나의 Link를 사용하는 방식이 적절하다. 기존 wrapper `role=button` 안의 Link 중첩을 그대로 복제하지 않는다. 지표 데이터가 없는 종목은 기존처럼 값 ‘—’와 비활성 조건을 유지하며 새 회사 합산 버튼을 발명하지 않는다.

## 메뉴의 두 단계

| 화면 | 상단 메뉴 | 지표 메뉴의 위치·뜻 |
|---|---|---|
| 메인 | 메인 활성 · 랭킹 링크 | 전체 순위용 지표 줄 없음 |
| 랭킹 | 메인 링크 · 랭킹 활성 | 헤더 아래: 시장 전체의 시가총액·PER 등 순위 |
| 회사·종목 상세 | 메인 링크 · 랭킹 탐색 강조 제안 | 기업명·요약 아래 본문 안: 선택한 회사·종목의 시가총액·PER 등 상세 |

데스크톱 헤더는 로고 → 메인·랭킹 → 검색 → 테마다. 검색을 적당히 줄여 메뉴가 들어갈 공간을 확보한다. 주 메뉴 선택은 먹색 면과 밝은 글자, 지표 선택은 금색 밑줄로 표현해 계층을 구분한다. 상세의 상단 전역 지표 줄은 제거하고 지표 메뉴를 회사 요약 아래로 옮긴다. 같은 ‘PER’가 전체 순위와 개별 종목 분석 사이에서 어디로 이동하는지 화면의 위치와 회사 문맥으로 구분한다.

기존 모바일 라이트 시안과 제품 코드는 이번 단계에서 변경하지 않는다. 모바일 메인 탐색은 기존 메뉴·하단 탐색의 기능을 유지해야 하며 이번 요청은 데스크톱 표현을 중심으로 비교한다.

## 시안

이전 최종 데스크톱 이미지의 좁은 편집으로 생성한다. 기존 실제 상세 캡처는 빠진 메인·랭킹과 종목 이동 기능의 근거로만 사용하며 과거의 카드 색과 그라디언트를 가져오지 않는다. 생성 이미지의 로고 영역은 비우고 실제 나눔명조800과 원본 별 SVG를 합성한다.

파일·정확한 프롬프트·PNG 출처는 `.impeccable/mocks/navigation/`에 보존한다. 생성 시안의 승인 상태는 `approved:false`이며 앞선 구조의 사용자 긍정 평가를 이번 새 메뉴·이동 표현의 최종 승인으로 대신하지 않는다.

최종 비교: `http://127.0.0.1:49673/navigation.html?theme=light`. 직전 `desktop-shell.html`과 연결해 메뉴·종목 이동의 수정 전후를 비교할 수 있다. 단일 화면 뷰어는 `navigation-preview.html?page=ranking&theme=light`이며 `page=detail`, `theme=dark`도 지원한다.

| 화면 | 정확한 생성·편집 프롬프트 |
|---|---|
| 랭킹 라이트 | [ranking-light.prompt.txt](../.impeccable/mocks/navigation/ranking-light.prompt.txt) |
| 랭킹 다크 | [ranking-dark.prompt.txt](../.impeccable/mocks/navigation/ranking-dark.prompt.txt) |
| 상세 라이트 | [detail-light.prompt.txt](../.impeccable/mocks/navigation/detail-light.prompt.txt) |
| 상세 다크 | [detail-dark.prompt.txt](../.impeccable/mocks/navigation/detail-dark.prompt.txt) |

이전 라이트 두 화면을 각각 한 번 편집하고 두 결과를 검토했다. 메뉴 계층과 버튼형 링크가 반영되어 구조 재생성은 추가하지 않았다. 이어 각 라이트를 참조해 다크 색상 편집을 한 번씩 했다. 회사 합산 화면의 두 종목은 미선택이며 우측 기존4개 모듈과 모든 예시 차트를 유지했다.

원본 크기는 랭킹 두 테마1491×1055, 상세 라이트1448×1086, 상세 다크1449×1086이다. 기존 이미지의 헤더 높이·패널 폭 차이는 남아 있다. 이번 편집은 두 요청에 한정했다. 랭킹의 메인 메뉴가 로고와 가까워 실제 폰트 합성은 데스크톱30px로 조정했다. 1440px에서 실제 로고의 오른쪽 끝은304.3px이고 메뉴와 겹치지 않는다. 브랜드 폰트·이름·가운데 원본 별은 유지했다.

## 확인

- 네 생성 PNG와 뷰어 복사본 총8개 PNG의 embedded prompt 검사: 누락0개.
- 뷰어 JavaScript 구문 검사 통과.
- 1440×1080에서 네 화면의 실제 폰트·이미지 로딩, 전체 이름, 메뉴와 로고의 간격, 가로 넘침 없음을 확인했다.
- 비교 페이지의 테마 전환과 단일 화면 링크의 테마 변경을 확인했다. 390×844에서 비교 뷰어가 한 열로 재배치되고 가로 넘침이 없음을 실제 viewport 관찰과 DOM에서 확인했다.
- 실제 로고가 합성된 네 개별 캡처와 라이트 비교 캡처는 `.impeccable/logo-review/review/navigation/`에 있다. 확인 값은 `render-validation.json`이다. 다크 비교 페이지의 별도 clip 캡처는 렌더 관찰과 다른 깨진 파일을 반환해 폐기했다. 네 개별 캡처는 각각 열어 정상 화면을 확인했다.

모바일 제품 시안과 생산 앱 소스는 변경하지 않았다. 이미지 안의 메인·랭킹·지표·종목 링크는 제안된 UI이며 아직 실제 제품 동작을 구현한 것은 아니다. 비교 페이지의 테마·크게 보기·이전 시안 링크만 동작한다. 메인 메뉴의 `/dashboard`, 랭킹의 `/` 목적지는 기존대로 유지하는 제안이다.
